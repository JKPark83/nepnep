## 1. 개요

### 1.1 한 줄 정의

**넵넵**은 대면 회의를 아이폰으로 녹음하면 **온디바이스**로 화자분리·전사·요약까지 끝내고, 완성된 회의록을 **Notion과 Google Docs에 자동으로 넣어주는** iOS 앱이다.

### 1.2 문제 정의

회의록 작성은 시간이 많이 드는 반복 업무이며, 기존 서비스는 각각 결정적인 공백이 있다.

| 서비스 | 한국어 전사 | 화자분리 | Notion/Docs 자동 정리 | 비고 |
|---|---|---|---|---|
| 클로바노트 | ◎ | ◎ | ✕ | 무료 월 300분 한도, 내보내기는 수동 복사 |
| Notion AI 회의록 | ○ | ✕ | ◎ (Notion만) | 화자 구분 불가 |
| Granola | ○ | △ | △ | Notion 연동이 유료 전용, 한국어 최적화 아님 |
| **넵넵** | **◎ (온디바이스)** | **◎ (온디바이스)** | **◎ (Notion + Docs)** | 무료 무제한, 프라이버시 |

→ **"한국어 + 화자분리 + Notion/Docs 자동 정리"를 모두 제공하는 앱은 시장에 없다.** 이 교집합이 넵넵의 존재 이유다.

### 1.3 핵심 차별점 (셀링 포인트)

1. **무료 무제한**: 온디바이스 파이프라인은 서버 비용이 0원이므로 시간 제한 없이 무료 제공. (클로바노트 무료 300분 대비 명확한 우위)
2. **프라이버시**: 무료 모드에서 녹음·전사 데이터가 기기 밖으로 절대 나가지 않는다. 보안에 민감한 사내 회의에도 사용 가능.
3. **자동 정리**: 회의 종료 → 몇 분 뒤 Notion DB에 회의록이 자동으로 생성되는 완결된 워크플로우.

## 2. 목표와 성공 지표

### 2.1 제품 목표

- 한국 직장인이 대면 회의에서 **"녹음 버튼 한 번"** 이외의 수작업 없이 회의록을 얻게 한다.
- 온디바이스 품질이 클로바노트 대비 **체감 동등 이상**임을 증명한다.

### 2.2 성공 지표 (출시 후 3개월 기준)

| 분류 | 지표 | 목표 |
|---|---|---|
| 품질 | 블라인드 비교 테스트에서 클로바노트 대비 선호도 | 50% 이상 |
| 품질 | 화자분리 오류율 (테스트 세트 기준 DER) | 20% 이하 |
| 활성화 | 첫 녹음 완료율 (설치 → 첫 회의록 생성) | 40% 이상 |
| 리텐션 | 주간 재사용율 (첫 회의록 생성 유저 기준 W1 리텐션) | 30% 이상 |
| 연동 | 회의록 생성 유저 중 Notion/Docs 연동 비율 | 50% 이상 |
| 수익 | 유료 전환율 (MAU 대비) | 3% 이상 |

### 2.3 품질 측정 방법

개발 초기에 **동일 녹음 파일 테스트 세트**를 구축한다.

- 구성: 2인/4인/6인 회의 × 조용한 회의실/시끄러운 카페 × 30분 내외, 최소 8개 파일
- 각 파일을 클로바노트와 넵넵 파이프라인에 동시 입력 → 전사 정확도(CER), 화자분리 정확도(DER), 블라인드 선호도를 기록
- 이 테스트 세트는 릴리즈마다 회귀 테스트로 재사용

## 3. 타겟 사용자

### 3.1 타겟 정의

대면 회의가 잦고, Notion 또는 Google Docs로 업무를 정리하는 **한국 직장인**. App Store 일반 공개.

### 3.2 페르소나

**P1. 스타트업 PM 김서연 (주 사용자)**
- 주 8회 이상 회의. 팀 위키가 Notion. 회의록 작성에 하루 1시간 이상 소모.
- 니즈: 회의 끝나면 Notion 회의록 DB에 자동으로 정리돼 있길 원함. 누가 무슨 말을 했는지(화자)가 중요.
- 유료 전환 가능성: 높음 (고품질·긴 회의).

**P2. 대기업 사원 박준호 (프라이버시 민감 사용자)**
- 사내 보안 정책상 녹음 데이터를 외부 서버에 올릴 수 없음.
- 니즈: 완전 온디바이스 처리. 회의록은 개인 Notion에만 보관.
- 유료 전환 가능성: 낮음, 그러나 무료 모드의 핵심 검증 사용자이자 입소문 채널.

**P3. 프리랜서/컨설턴트 이하늘 (인터뷰 사용자)**
- 고객 미팅·인터뷰가 잦음. 회의록을 Google Docs로 고객과 공유.
- 니즈: 인터뷰 템플릿(질문/답변 구조), Google Docs 내보내기.

### 3.3 지원 기기 (의사결정 확정)

- **iOS 26 이상 + Apple Intelligence 지원 기기(iPhone 15 Pro 이상)만 지원.**
- Foundation Models 미지원 기기(iPhone 15 Pro 미만)는 **지원하지 않는다.** App Store 요구 기기 사양으로 명시하고, 미지원 기기 설치를 차단한다.
- 근거: 무료 요약이 안 되는 반쪽 경험을 제공하느니 제품을 단순하게 유지한다. 시장 축소는 감수한다(리스크 §12-R2 참고).

## 4. 범위 (Scope)

### 4.1 MVP 포함

| # | 기능 | 요약 |
|---|---|---|
| F1 | 회의 녹음 | 아이폰 마이크, 백그라운드 녹음, 중단 복구 |
| F2 | 온디바이스 전사 | 전사 엔진 2종 내장(SpeechTranscriber / WhisperKit), 설정에서 선택 |
| F3 | 온디바이스 화자분리 | FluidAudio (pyannote Core ML 포팅) |
| F4 | 화자 이름 지정 | "화자 1, 2…" → 이름 라벨링 |
| F5 | 온디바이스 요약 | Foundation Models, 회의 유형별 템플릿 4종 |
| F6 | 회의록 확인·수정 | 요약/할 일/결정사항/전문 편집 |
| F7 | Notion 내보내기 | 사용자 지정 DB에 페이지 자동 생성 |
| F8 | Google Docs 내보내기 | 지정 폴더에 문서 생성 |
| F9 | 유료 구독 (IAP) | 클라우드 고품질 STT+요약, 월 6,900원 |
| F10 | 백그라운드 처리 | 처리 중 앱 이탈 허용, 완료 로컬 알림 |
| F11 | 저장공간 관리 | 오디오 일괄 삭제 등 수동 관리 |

### 4.2 명시적 제외 (MVP에서 안 함)

- **BYO API 키** — 추후 고급 설정으로.
- **온라인 화상회의(Zoom 등) 오디오 캡처** — iOS 기술 제약. **오디오 파일 임포트도 2차.**
- **실시간 자막, 안드로이드, 웹 버전.**
- **화자 음성 프로필 재사용** (한 번 이름 지정한 화자를 다음 회의에서 자동 인식) — 2차 과제.
- **커스텀 요약 템플릿 편집** — 고정 4종만 제공, 편집은 2차.
- **iCloud 동기화/기기 간 공유** — 데이터는 기기 로컬 단일 저장.
- **계정/회원가입** — 없음 (§9.4).
- **오디오 자동 삭제 정책** — 무제한 보관 + 수동 삭제만.

## 5. 핵심 사용자 플로우

### 5.1 메인 플로우 (해피 패스)

```
[회의 전]
1. 앱 실행 → 홈에서 녹음 버튼 탭 → 회의 유형 선택(일반/1on1/인터뷰/스탠드업, 기본값: 일반)
2. 폰을 테이블에 놓음. 화면 잠금·앱 전환해도 백그라운드 녹음 유지

[회의 후]
3. 정지 탭 → 온디바이스 처리 자동 시작 (전사 → 화자분리 → 병합 → 요약)
   - 앱을 나가도 백그라운드에서 계속 처리, 완료 시 로컬 알림
4. 알림 탭 → 회의록 화면 진입
5. 화자 라벨("화자 1, 2…")에 이름 지정 → 전체 대화록에 즉시 반영
6. 요약·할 일·결정사항 확인, 필요 시 인라인 수정
7. "내보내기" 탭 → 연결된 Notion DB에 페이지 자동 생성 (또는 Google Docs)
8. 완료 토스트에서 "Notion에서 열기" 링크 제공
```

### 5.2 유료 사용자 분기

- 3단계 처리 시작 전(또는 녹음 시작 화면에서) **"고품질 클라우드 처리" 토글** 노출.
  - 무료 사용자: 토글 탭 시 페이월 표시.
  - 유료 사용자: 토글 ON 시 오디오를 서버 프록시 경유로 클라우드 STT+요약 처리. 이때 "이 회의의 오디오가 암호화되어 외부 서버로 전송됩니다" 고지.

### 5.3 최초 실행 온보딩

```
1. 가치 제안 3장 (무료 무제한 / 프라이버시·온디바이스 / Notion·Docs 자동 정리)
   - 클로바노트 대비 차별점을 이 단계에서 명확히 전달 (리스크 §12-R4 대응)
2. 마이크 권한 요청 (사용 직전 컨텍스트와 함께)
3. 알림 권한 요청 ("처리 완료를 알려드리기 위해")
4. 음성 모델 다운로드 (SpeechTranscriber 한국어 에셋 + FluidAudio 모델, Wi-Fi 권장 안내. WhisperKit 모델은 온보딩에서 받지 않고 설정에서 엔진 전환 시 다운로드)
5. Notion/Google 연동 제안 — "나중에 하기" 허용 (첫 내보내기 시점에 다시 유도)
```

### 5.4 예외 플로우

| 상황 | 동작 |
|---|---|
| 녹음 중 전화 수신 | 오디오 세션 인터럽트 → 녹음 자동 일시정지, 통화 종료 후 자동 재개. 구간 누락을 타임라인에 표시 |
| 녹음 중 앱 강제종료/크래시 | 녹음 파일은 청크 단위로 디스크에 순차 기록. 재실행 시 "복구된 녹음" 으로 제시 |
| 처리 중 백그라운드 시간 소진 | 체크포인트 저장 후 중단 → 다음 포그라운드 진입 시 이어서 처리. 홈 화면에 "처리 대기 중" 배지 |
| 저장공간 부족 | 녹음 시작 시 예상 용량 체크(1시간 ≈ 60MB 기준), 부족 시 시작 차단 + 저장공간 관리 화면 유도 |
| Notion 토큰 만료/권한 회수 | 내보내기 실패 시 재연동 유도. 작성된 회의록은 로컬에 그대로 보존 |
| 클라우드 처리 실패 (네트워크/서버) | 자동 재시도 2회 → 실패 시 "온디바이스로 대신 처리" 폴백 제안. 클라우드 사용량 차감 없음 |

## 6. 기능 상세 요구사항

각 요구사항은 `[MUST]`(MVP 필수) / `[SHOULD]`(MVP 내 우선순위 하) 로 표기한다.

### F1. 회의 녹음

- **F1-1 [MUST]** AVAudioEngine 기반 마이크 녹음. 포맷: 16kHz mono(전사·화자분리 입력 규격) 원본 보존.
- **F1-2 [MUST]** 백그라운드 녹음: `audio` 백그라운드 모드. 화면 잠금·앱 전환 시에도 지속. 다이나믹 아일랜드/잠금화면에 녹음 상태 표시(Live Activity).
- **F1-3 [MUST]** 녹음 화면: 경과 시간, 오디오 레벨 미터, 일시정지/재개, 정지.
- **F1-4 [MUST]** 크래시 내구성: 오디오를 N초 단위 청크로 디스크에 순차 기록. 비정상 종료 시 복구.
- **F1-5 [MUST]** 오디오 세션 인터럽트(전화·시리 등) 처리: 자동 일시정지·재개, 누락 구간 기록.
- **F1-6 [SHOULD]** 최대 녹음 길이 가드: 4시간 도달 시 경고 후 자동 분할 저장.
- **F1-7 [SHOULD]** 녹음 중 회의 유형·제목 변경 가능.

### F2. 온디바이스 전사

- **F2-1 [MUST]** 전사 엔진 2종 내장 (의사결정 확정 D9):
  - **기본**: iOS 26 `SpeechAnalyzer`/`SpeechTranscriber` (한국어). 속도·배터리 우위.
  - **대안**: **WhisperKit** (Whisper large-v3-turbo, Core ML). 한국어 품질 비교용.
  - 두 엔진 모두 단어/구 단위 타임스탬프 확보(화자분리 병합 규격 동일).
- **F2-2 [MUST]** 설정 > 전사 엔진에서 사용자가 선택 가능. 기본값은 SpeechTranscriber. WhisperKit 최초 선택 시 모델 다운로드(약 600MB, Wi-Fi 권장) 후 활성화. 처리 속도·배터리 차이를 선택 UI에 고지.
- **F2-3 [MUST]** 엔진별 모델 에셋 다운로드 상태 관리: SpeechTranscriber 한국어 에셋은 온보딩(§5.3)에서, WhisperKit 모델은 엔진 전환 시점에 다운로드. 미설치 상태에서는 다운로드 유도.
- **F2-4 [MUST]** 녹음 종료 후 파일 기반 일괄 전사. (실시간 스트리밍 전사는 채택하지 않음 — 배터리·복잡도 사유, §의사결정 D6)
- **F2-5 [SHOULD]** 영어 혼용 발화(한국어 회의 중 영단어) 전사 품질을 테스트 세트에 포함해 **엔진별로** 측정. M0 스파이크에서 두 엔진의 CER·처리 시간을 비교 실측.

### F3. 온디바이스 화자분리

- **F3-1 [MUST]** FluidAudio(pyannote Core ML 포팅, MIT)로 화자 세그먼트 추출.
- **F3-2 [MUST]** 전사 타임스탬프 × 화자 세그먼트 매칭으로 **화자별 발화 단위의 대화록** 구성. 경계 겹침 시 세그먼트 중심점 기준 배정.
- **F3-3 [MUST]** 지원 화자 수: 2~8명. 자동 추정하되 사용자가 사후에 "화자 병합"(같은 사람이 둘로 나뉜 경우) 가능.
- **F3-4 [SHOULD]** 화자 분리 신뢰도가 낮은 발화에 시각적 표시(회색 처리 등).

### F4. 화자 이름 지정

- **F4-1 [MUST]** 회의록 화면에서 화자 칩("화자 1") 탭 → 이름 입력 → 해당 화자의 모든 발화에 즉시 반영.

### F5. 온디바이스 요약

- **F5-1 [MUST]** Apple Foundation Models로 요약 생성. 입력: 화자 라벨 포함 전사 전문. 긴 회의는 청크 분할 → 부분 요약 → 통합 요약(map-reduce).
- **F5-2 [MUST]** 회의 유형별 템플릿 4종 (의사결정 확정):

| 템플릿 | 섹션 구성 |
|---|---|
| 일반 회의 (기본) | 한 줄 요약 / 주요 논의 / 결정사항 / 할 일(담당자·기한) |
| 1on1 | 한 줄 요약 / 주요 대화 주제 / 피드백·합의사항 / 팔로업 |
| 인터뷰 | 한 줄 요약 / 질문별 답변 정리 / 주요 인사이트 / 팔로업 |
| 스탠드업 | 참석자별 (한 일 / 할 일 / 블로커) / 공지사항 |

- **F5-3 [MUST]** 할 일 항목은 구조화 출력(내용/담당자/기한)으로 추출. Foundation Models의 guided generation 사용.
- **F5-4 [MUST]** 요약 실패(모델 오류·컨텍스트 초과) 시에도 전사·화자분리 결과는 보존하고, "요약 다시 시도" 제공.

## 9. 기술 아키텍처

### 9.1 클라이언트

- **스택**: SwiftUI, iOS 26+, Swift Concurrency. 로컬 저장은 SwiftData(또는 GRDB — 구현 시 결정), 오디오 파일은 앱 컨테이너 파일시스템.
- **무료 파이프라인 (전부 온디바이스, 서버비 0원)**:

```
AVAudioEngine 녹음 (청크 저장)
  → SpeechTranscriber 또는 WhisperKit 전사 (설정에서 선택, 타임스탬프 포함)
  → FluidAudio 화자분리 (화자 세그먼트)
  → 타임스탬프 매칭 병합 (화자별 발화록)
  → Foundation Models 요약 (템플릿별 guided generation)
```

- **유료 파이프라인**:

```
오디오 업로드 → [서버 프록시] → 리턴제로 RTZR STT (화자분리 포함)
                              → Claude 요약
             ← 회의록 JSON 수신 → 로컬 저장 (이후 흐름 동일)
```

### 9.2 서버 (경량 프록시 1개)

- 역할: ① API 키 은닉 ② App Store 구독 영수증 검증 ③ 클라우드 사용량(월 20시간) 카운팅 ④ STT·요약 API 중계.
- 원칙: 상태 최소화. 저장 데이터는 (익명 기기 식별자, 구독 상태, 월 사용량)뿐. 오디오·텍스트는 무저장 중계.
- 스택: 구현 시 결정(경량 Node/Swift 서버 + 서버리스 가능). PRD 수준에서는 역할만 고정.

### 9.3 외부 연동

| 연동 | 방식 | 비고 |
|---|---|---|
| Notion | OAuth public integration, Pages/Databases API | 토큰 Keychain, 블록 분할 append |
| Google Docs | OAuth, Docs API + Drive API (`drive.file`) | 최소 권한 scope |
| 리턴제로 (RTZR STT) | 서버 프록시 경유 | 클라우드 STT + 화자분리 |
| Anthropic | 서버 프록시 경유 | 클라우드 요약 |
| App Store | StoreKit 2 + App Store Server API | 구독 검증은 서버 |

### 9.4 계정 모델 (의사결정 확정: 계정 없음)

- 회원가입·로그인 없음. 모든 데이터는 기기 로컬.
- 구독 자격은 App Store 영수증으로 판별(기기 복원·재설치 시 구매 복원).
- 클라우드 사용량 카운팅 키는 App Store `appAccountToken`/원본 거래 ID 기반 익명 식별자.
- 트레이드오프 수용: 기기 변경 시 회의록 데이터 이전 불가(수동 내보내기로 대체), iCloud 동기화는 2차 검토.

### 9.5 데이터 모델 (로컬)

```
Meeting
 ├ id, title, type(일반/1on1/인터뷰/스탠드업), createdAt, duration
 ├ status (recording / processing(단계) / done / failed)
 ├ audioFileURL, audioSize
 ├ processingMode (onDevice / cloud)
 ├ exportLinks [notionPageURL?, googleDocURL?]
 ├ Speaker[] (id, label "화자 1", customName?)
 ├ Utterance[] (speakerId, text, startTime, endTime, confidence)
 └ Summary (templateType, oneLiner, sections[], decisions[],
            actionItems[](content, assignee?, due?, done))
```

## 11. 릴리즈 계획

### M0. 기술 검증 스파이크 (최우선 게이트)

- 실기기(iPhone 15 Pro급)에서 30분 한국어 회의 녹음 → SpeechTranscriber + FluidAudio 파이프라인 실행.
- 측정: 전사 정확도, 화자분리 품질(2인/4인, 소음 환경 포함), 처리 시간, 발열·배터리.
- **통과 기준**: 클로바노트 블라인드 비교 "체감 동등", 30분 처리 ≤ 10분. **미통과 시 설계 재검토(클라우드 우선 전환 등) — 이후 마일스톤 착수 금지.**

### M1. 녹음 코어
녹음 화면 + 백그라운드 오디오 세션 + 청크 저장·복구 (F1)

### M2. 처리 파이프라인 + 대화록
전사·화자분리·병합, 백그라운드 처리·체크포인트·알림, 대화록 UI + 화자 지정 (F2·F3·F4·F10)

### M3. 요약 + 회의록
Foundation Models 템플릿 4종 요약, 회의록 상세·편집 (F5·F6)

### M4. Notion 내보내기
OAuth, DB 선택, 페이지 생성 (F7) → **이 시점에 TestFlight 베타**

### M5. 수익화 + Google Docs
서버 프록시, IAP·클라우드 파이프라인 (F9), Google Docs (F8), 저장공간 관리 (F11)

### M6. 출시
온보딩 완성, App Store 심사(백그라운드 오디오·구독·개인정보 라벨), 테스트 세트 회귀 통과

## 14. 오픈 이슈 (PRD 이후 결정)

1. 서버 프록시 기술 스택·호스팅 (구현 계획 단계에서 결정)
2. 로컬 DB 선택: SwiftData vs GRDB (M1 착수 시 결정)
3. 연간 구독 상품·가격 (출시 후 데이터 기반)
4. 앱 이름 "넵넵"의 App Store 등록 가능 여부·상표 확인
5. 클라우드 요약에 쓸 Claude 모델 티어 확정 (품질 vs 원가, M5에서 A/B)
6. RTZR STT 기업 계약 조건·단가 확정 및 대안 벤더(AssemblyAI 등) 비교 검증 — M5에서 동일 테스트 세트(§2.3)로 실측
7. WhisperKit 탑재 모델 확정 (large-v3-turbo vs large-v3, 용량·속도·한국어 CER 트레이드오프 — M0에서 실측)
