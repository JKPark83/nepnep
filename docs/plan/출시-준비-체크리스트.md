# 넵넵 출시 준비 — 사용자 작업 체크리스트

코드는 M0~M6까지 모두 구현·테스트 완료된 상태다. 여기 있는 항목은 전부
외부 콘솔·계정 작업이라 코드로 대신할 수 없다. 위에서부터 순서대로 하면
막히는 구간 없이 진행된다.

> `683c4fa`에서 유료화(구독·클라우드 처리)를 걷어내 앱은 전 구간 온디바이스로
> 동작한다. 그래서 이전 판에 있던 IAP 상품 등록, Sandbox 테스터, 유료 앱 계약,
> RTZR·Anthropic·Blob·KV 환경변수 항목은 모두 삭제했다.

## A. 앱 기능 잠금 해제 (가장 먼저)

### A-1. Google OAuth 클라이언트 ID — ✅ 코드 반영 완료

발급받은 iOS 클라이언트 ID를 `ios/NepNep/Core/Export/GoogleAuthService.swift`에 적용했다.

| 항목 | 값 |
|---|---|
| 클라이언트 ID | `223884355131-tan8q317404etpr6005lmbpeh979j788.apps.googleusercontent.com` |
| 콜백 스킴 (자동 계산) | `com.googleusercontent.apps.223884355131-tan8q317404etpr6005lmbpeh979j788` |
| 리다이렉트 URI | 위 스킴 + `:/oauth2redirect` |

`ASWebAuthenticationSession`이 리다이렉트를 직접 받으므로 Info.plist에
URL 스킴을 등록할 필요는 없다.

**아직 남은 Google 콘솔 작업**

- [ ] **API 및 서비스 → 라이브러리**에서 `Google Docs API`, `Google Drive API` 사용 설정
- [ ] **OAuth 동의 화면**에 범위 `.../auth/documents`, `.../auth/drive.file` 추가
- [ ] 테스트 사용자에 본인 Google 계정 등록 (게시 전에는 등록된 계정만 로그인된다)
- [ ] ⚠️ `documents`는 민감한 범위라 앱을 공개 게시하려면 Google 검토가 필요할 수 있다.
      검토 기간이 길어질 수 있으니 일정에 반영한다

### A-2. Notion 시크릿 로테이션 — 릴리스 전 필수

현재 시크릿이 대화 중에 노출됐다. Notion Integrations 설정에서 시크릿을 재발급하고
Vercel 환경변수 `NOTION_CLIENT_SECRET`만 새 값으로 갱신한다. 코드 수정은 필요 없다.

- [ ] Notion 시크릿 재발급 → Vercel `NOTION_CLIENT_SECRET` 갱신 → 재배포

서버가 읽는 환경변수는 이 둘뿐이다 (`server/src/routes/notionOAuth.ts`).

| 변수 | 상태 |
|---|---|
| `NOTION_CLIENT_ID` | 설정 완료 |
| `NOTION_CLIENT_SECRET` | A-2에서 갱신 |

## B. TestFlight 업로드 준비

`.github/workflows/testflight.yml`이 `main` 푸시(또는 수동 `workflow_dispatch`)에
반응해 빌드·서명·업로드까지 전부 처리한다. 아래 4개 리소스와 시크릿 5종만
채워지면 사람 손이 더 갈 일은 없다.

`testflight-credentials` 스킬이 B-1·B-3·B-4를 API로 대신 처리한다
("TestFlight 올릴 준비 해줘").

### B-1. App ID 등록

번들 ID `com.nepnep.NepNep`. 위젯 확장(`com.nepnep.NepNep.widgets`)은 아카이브
과정에서 `-allowProvisioningUpdates`가 자동 생성하므로 손으로 등록하지 않는다.

- [ ] App ID `com.nepnep.NepNep` 등록

### B-2. App Store Connect 앱 레코드 — 브라우저에서만 가능

API가 없어 직접 만들어야 한다. 워크플로가 빌드 번호를 정할 때 번들 ID로 앱을
조회하므로, 첫 실행 전에 반드시 존재해야 한다.

- [ ] [앱 등록](https://appstoreconnect.apple.com/apps) — 플랫폼 iOS, 번들 ID `com.nepnep.NepNep`
- [ ] 등록 후 표시되는 **Apple ID(숫자)** 기록

### B-3. ASC API 키 발급 — 브라우저에서만 가능

- [ ] [Integrations → 팀 키](https://appstoreconnect.apple.com/access/integrations/api)에서
      **App Manager** 권한으로 키 생성 (Developer 권한이면 생성 API가 403으로 막힌다)
- [ ] `AuthKey_<KEY_ID>.p8` 내려받기 — **단 한 번만 받을 수 있다**
- [ ] Key ID(10자)와 Issuer ID(UUID) 기록

### B-4. Apple Distribution 인증서 → `.p12`

- [ ] 인증서 발급 후 `.p12` 패키징 (개인키는 로컬을 벗어나지 않는다)
- [ ] `.p12`가 CI와 동일한 방식으로 키체인에 임포트되는지 검증

### B-5. GitHub Actions 시크릿 5종

| 시크릿 | 출처 |
|---|---|
| `ASC_KEY_ID` | B-3 |
| `ASC_ISSUER_ID` | B-3 |
| `ASC_KEY_P8` | B-3의 `.p8` 파일 내용 |
| `DIST_CERT_P12_BASE64` | B-4의 `.p12`를 base64 한 줄로 |
| `DIST_CERT_PASSWORD` | B-4에서 생성된 비밀번호 |

- [ ] 5종 등록 후 `gh secret list`로 이름·시각 확인 (값은 출력되지 않는다)
- [ ] `dev` → `main` 머지로 첫 업로드 실행

첫 업로드는 20~35분, 이후 ASC 처리에 5~15분이 더 걸린다.
수출 규정은 `ITSAppUsesNonExemptEncryption: false`를 `ios/project.yml`에 박아
뒀으므로 빌드마다 답할 필요가 없다.
