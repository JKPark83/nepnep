# 넵넵 출시 준비 — 사용자 작업 체크리스트

코드는 M0~M6까지 모두 구현·테스트 완료된 상태다. 여기 있는 항목은 전부
외부 콘솔·계정 작업이라 코드로 대신할 수 없다. 위에서부터 순서대로 하면
막히는 구간 없이 진행된다.

---

## A. 앱 기능 잠금 해제 (가장 먼저)

### A-1. Google OAuth 클라이언트 ID 발급 — Google Docs 내보내기가 이것 없이는 동작 안 함

1. [Google Cloud Console](https://console.cloud.google.com/) → 프로젝트 생성
2. **API 및 서비스 → 라이브러리**에서 `Google Docs API`, `Google Drive API` 사용 설정
3. **OAuth 동의 화면** 구성
   - 사용자 유형: 외부
   - 범위 추가: `.../auth/documents`, `.../auth/drive.file`
   - ⚠️ `documents`는 민감한 범위라 앱을 공개 게시하려면 Google 검토가 필요할 수 있다.
     검토 기간이 길어질 수 있으니 일정에 반영하거나, 테스트 사용자 등록으로 먼저 검증한다
4. **사용자 인증 정보 → OAuth 클라이언트 ID 만들기** → 애플리케이션 유형 **iOS**
   - 번들 ID: `com.nepnep.NepNep`
5. 발급된 클라이언트 ID를 코드에 반영
   - 파일: `ios/NepNep/Core/Export/GoogleAuthService.swift` 15번째 줄
   - `static let clientID = "GOOGLE_CLIENT_ID_MISSING"` → 발급받은 값으로 교체
   - 콜백 URL 스킴은 클라이언트 ID를 뒤집어 코드가 자동 계산하므로 추가 설정 불필요

### A-2. Notion 시크릿 로테이션 — 릴리스 전 필수

현재 시크릿이 대화 중에 노출됐다. Notion Integrations 설정에서 시크릿을 재발급하고
Vercel 환경변수 `NOTION_CLIENT_SECRET`만 새 값으로 갱신한다. 코드 수정은 필요 없다.

## B. 클라우드 처리 활성화 (프로 구독 기능)

Vercel 프로젝트 설정에서 아래를 준비한다. 스토리지 2개는 연결하면 환경변수가
자동으로 주입되므로 직접 입력할 필요가 없다.

### B-1. 스토리지 연결 (Vercel → Storage)

| 스토리지 | 용도 | 자동 주입되는 변수 |
|---|---|---|
| Blob | 오디오 임시 업로드 | `BLOB_READ_WRITE_TOKEN` |
| Upstash Redis (Marketplace) | 월 사용량 카운터 | `KV_REST_API_URL`, `KV_REST_API_TOKEN` |

### B-2. 직접 입력할 환경변수 (Vercel → Settings → Environment Variables)

| 변수 | 값 | 발급처 |
|---|---|---|
| `RTZR_CLIENT_ID` | | [리턴제로 VITO](https://developers.rtzr.ai/) 가입 후 발급 |
| `RTZR_CLIENT_SECRET` | | 위와 동일 |
| `ANTHROPIC_API_KEY` | | [Anthropic Console](https://console.anthropic.com/) |
| `APPLE_ENVIRONMENT` | `Sandbox` (테스트) / `Production` (출시) | — |
| `APP_APPLE_ID` | App Store Connect의 앱 ID(숫자) | C-1 완료 후 |
| `APP_BUNDLE_ID` | (선택) 기본값 `com.nepnep.NepNep` | — |
| `NOTION_CLIENT_ID` | 설정 완료 | |
| `NOTION_CLIENT_SECRET` | A-2에서 갱신 | |
| `SESSION_SECRET` | 설정 완료 | |

## C. 구독 상품 등록

### C-1. App Store Connect 앱 등록

1. 앱 등록 — 번들 ID `com.nepnep.NepNep`
2. 등록 후 표시되는 **Apple ID(숫자)**를 B-2의 `APP_APPLE_ID`에 입력

### C-2. 구독 상품

| 항목 | 값 |
|---|---|
| 제품 ID | `com.nepnep.pro.monthly` |
| 유형 | 자동 갱신 구독 (구독 그룹 1개 생성) |
| 가격 | 월 ₩6,900 |
| 혜택 표기 | 월 20시간 클라우드 고품질 처리 |

### C-3. Sandbox 테스터 계정 생성

App Store Connect → 사용자 및 액세스 → Sandbox 테스터. 구매·복원 테스트에 필요하다.

## D. 배포와 검증

### D-1. 서버 배포

`server/` 배포 후 아래 두 주소가 실제로 열리는지 확인한다. 심사에서 요구하는 링크다.

- https://nepnep-server.vercel.app/privacy
- https://nepnep-server.vercel.app/terms

### D-2. 회귀 테스트

`docs/plan/m6-regression.md`의 R1~R9를 실기기에서 실행하고 결과를 기록한다.
R4(Google 내보내기)는 A-1, R5·R6(구독·클라우드)은 B·C가 끝나야 실행 가능하다.

### D-3. 실동작 검증이 필요한 미확인 구간

코드는 문서 기준으로 작성했지만 실제 통신을 아직 못 해본 부분이다. 클라우드
E2E를 돌릴 때 여기서 문제가 나면 알려달라.

- Vercel Blob 업로드 프로토콜 (`x-api-version: 7` 헤더를 붙인 PUT 방식)
- 리턴제로 STT 제출·폴링 응답 형식
